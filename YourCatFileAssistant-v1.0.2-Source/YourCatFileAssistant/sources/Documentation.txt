# 桌面程序架构

## 模块边界

`CatFileAssistant.Core` 不引用 WPF、FFmpeg 进程或本机设置。它定义转换请求、结果、媒体信息、结构化错误，以及串行任务编排和猫咪状态规则。

`CatFileAssistant.Infrastructure` 实现 `IConversionEngine`。FFprobe 负责识别媒体，FFmpeg 负责转换；本模块也负责输入校验、临时输出与最终结果、设置、诊断日志和引擎进程收尾。

`CatFileAssistant.Desktop` 是 WPF/MVVM 程序。ViewModel 接收用户操作，维护可观察的队列和显示状态；窗口与猫咪组件负责布局和交互。WPF 控件不直接拼接转换命令或删除转换文件。

```mermaid
flowchart LR
    UI[WPF 窗口与猫咪组件] --> VM[MainViewModel]
    VM --> Import[共用导入服务]
    VM --> Queue[Core 串行队列]
    Import --> Engine[IConversionEngine]
    Queue --> Engine
    Engine --> Probe[本机 FFprobe]
    Engine --> Convert[本机 FFmpeg]
    Convert --> Temp[任务专属临时输出]
    Temp --> Check[媒体与格式检查]
    Check --> Final[提交最终文件]
```

## 稳定接口

- `ConversionRequest` 包含任务标识、源文件路径、格式预设和输出目录。源路径用于本机执行；未来平台适配可以在应用层将平台文件引用解析为执行器能使用的输入。
- `FormatPreset` 使用稳定英文 `Id`，并记录显示名称、扩展名、引擎预设键、转换模式、容器和预期编码。中文名称用于展示，不参与选择与判定。
- `MediaInfo` 描述视频和音频流、时长、实际容器及编码；视频检测与映射排除音频封面等附带图片。
- `IConversionEngine` 提供 `ProbeAsync` 和 `ConvertAsync`，接收取消标记及可选进度观察者。结果使用 `Completed`、`Failed`、`Cancelled` 等任务状态，不以界面文案判断成功。
- V0.3 在 `ConversionRequest` 末尾增加可空 `CompressionOptions`；不传时仍走原转换路径。标准档位以每个源文件的字节数计算上限，自定义上限直接传入字节数。`ConversionResult.Statistics` 返回源大小、最终大小、目标、尝试次数及已符合上限标识。
- V0.4 增加 `ConversionMode.Gif`、`GifQualityLevel` 和 `GifOptions`，请求末尾追加可空 `Gif`，缺省为中档；结果末尾追加 `GifStatistics` 返回源大小和输出大小。GIF 与压缩选项不能同时启用。
- `MediaInfo` 增加尺寸、帧率、音轨与字幕信息、透明能力及动画数据。动画总时长、帧延时与循环设置不依赖可能缺失的 `format.duration`。
- `ConversionError` 含稳定错误码、友好说明、建议操作、诊断标识和可选技术详情。用户默认看到说明和建议，技术详情在高级区域展开。
- `SerialConversionQueue` 逐项执行快照中的请求，收集每项结果。失败继续；取消停止开始后续请求。显示观察者异常不会改变已成功提交的结果。

`shared/presets.json` 是格式标识的来源，运行时经目录加载器校验。`shared/design-tokens.json` 记录视觉规范，桌面资源与后续平台设计应对齐这些数值。新增格式必须同时补齐引擎预设映射及真实媒体验收。

## V0.3 压缩路径

压缩与转换复用 `IConversionEngine` 和串行执行器，界面以任务操作类型隔离显示、设置应用范围和启动批次。压缩导入根据扩展名选择媒体检查，再使用实际媒体信息筛选可用输出格式。能力表是允许输出格式的唯一来源，不直接把源扩展名转换为任意编码器参数。

压缩请求最多生成八轮候选输出，每轮重新读取源文件。音视频按完整时长与各音轨分配码率；图片按质量和尺寸调整；GIF 与动态 WebP 采用独立的完整动画路径。输出实际大小不超过目标并通过媒体检查后才提交。不能保留内容或仍然超限时失败，候选文件只在任务拥有的临时目录中清理。

动态 WebP 使用随包的动画解码、WebP 逐帧编码与动画封装，完整画布帧设置 NO_BLEND 标记，避免半透明区域逐帧累积。编码后检查并修正末帧时长、保留循环设置；GIF 保存帧延时和循环，避免静态第一帧转换。透明背景能力参与格式筛选。

## V0.4 视频转 GIF

GIF 使用独立页面和任务类别；普通转换、压缩、GIF 分别启动和操作队列，原四种转换继续共享普通转换队列。GIF 修改档位遵循选中可编辑行优先的规则，已完成记录不受影响。设置追加 GIF 档位，旧设置缺省或非法值回退中档。

GIF 只接收有实际视频流的输入，排除封面流。引擎按主视频逐帧时间戳计算时长和抽帧，不将较长音轨计入输出时长。五档独立控制最长边、FPS 上限与颜色数，不使用压缩目标字节数。逐帧调色板避免缓存整段视频；原画保留所有解码帧，时间量化无法安全表示时失败并建议换档。

输出独立检查 GIF 图像块、帧延时、循环、尺寸和完整解码，并校正末帧停留时间；只有一轮时长误差不超过 20 毫秒才提交。不依赖普通图片的第一帧路径，也不套用要求保留音轨和字幕的压缩校验。GIF 无音轨和独立字幕，原文件与输出大小单独展示。

## 转换与退出的生命周期

导入和拖放共用输入检查，先校验扩展名、可读取性及实际媒体流。转换使用参数列表启动子进程，stdout 的进度与 stderr 的诊断异步读取，避免把界面线程阻塞在转换上。

每个任务先在目标目录保留唯一 `.cat-conversion-…` 文件，随后让 FFmpeg 写入该文件。转换退出码、文件非空、实际容器与编码均通过检查后才提交最终名称。提交避开已存在的文件与目录，以序号生成新名称；源文件和最终结果不进入临时清理逻辑。

任务提交成功后清除临时文件所有权，后续进度或界面观察者出错仍保留成功结果。失败和取消只清理任务拥有的临时文件；进程终止后等待退出并排空输出流，随后释放资源。

停止按钮取消当前任务，未开始的任务保持 `Pending`。关闭忙碌窗口时默认“继续转换”；选择“停止并退出”后取消任务，等待队列与子进程收尾，再关闭窗口。空闲窗口按正常流程退出。

## 猫咪状态与显示

`JobStatus` 表示每个任务的生命周期；`AssistantState` 表示品牌呈现。猫咪状态不能写入格式预设，也不能通过匹配中文文案计算。

| 状态 | 触发与显示 |
|---|---|
| `IDLE` | 等待操作；主动停止后显示“已停止” |
| `DRAGGING` | 可接收文件进入拖放区域，轻微高亮；离开恢复原状态 |
| `PROCESSING` | 显示当前任务名称，仅切换任务时改变文案 |
| `SUCCESS` | 本批次全部成功，轻微播放一次完成动画 |
| `ERROR` | 本批次存在失败，显示数量与“查看原因” |

完成或错误状态保持到添加文件、清空或开始下一批次。处理中禁止导入与格式修改；进度独立更新。空队列使用中央大区域，有队列时猫咪移入紧凑状态栏。隐私说明在空状态底部与侧栏底部按条件显示，避免同屏重复。

## V0.5 压缩包路径

压缩包使用独立 `IArchiveEngine`、`ArchiveRequest`、`ArchiveProgress`、`ArchiveResult` 与 `SerialArchiveQueue`，不向媒体请求添加伪造的 MediaInfo/FormatPreset。创建接收多输入，解压接收单包；结果明确区分文件和目录。Desktop 维护独立归档行和页面，但复用全局忙碌、停止、窗口退出和猫咪反馈生命周期。

Infrastructure 将任务经匿名 stdin 管道交给独立工作进程，只传 DLL 路径到命令行。工作进程通过官方完整 x64 DLL 的非注册式工厂、归档回调和受控读写流执行。其资源受到 Windows Job Object 的 2 GiB 内存上限和关闭即终止控制；取消五秒未结束时父进程终止它。

创建先枚举输入、去重和映射相对路径，再生成本任务快照，编码并受控解码校验。解压完整预检路径和条目类型，再一次性提取所有已验证条目；每次实际写入按累计限额计数，TAR 外层中间文件也计入预算。临时目录由父进程指定唯一直接子路径，由工作进程在输入清单冻结后创建，失败和强制终止可安全清理该任务路径。

单文件及整目录以无覆盖移动提交。同名自动编号，成功后清理逻辑不再拥有最终结果。7Z 分卷先校验完整包，再切片、校验字节重组与归档内容，最后以目录整体提交。解压通用切片提供连续可 Seek 的输入流；RAR 原生卷使用限定同目录回调。

工作进程源码及互操作层按 LGPL 2.1 或更高版本单独随包提供，官方对应完整源码和许可同时提供。设置仅保存非敏感偏好，宽容读取新增枚举，不因非法新字段丢失旧版设置。

## V0.6 密码恢复路径

恢复使用独立 `RecoveryRequest`、`RecoveryProgress`、`RecoveryResult`、`IPasswordRecoveryEngine` 和 `SerialRecoveryQueue`。请求快照包含方式、位数、强度、校验限额和会话内常用数字，不包含输出目录。Desktop 维护独立页面和行模型，复用全局忙碌、取消、退出和猫咪反馈生命周期。

Core 原创候选规则将常用搜索分成原值、派生、内置模式三个去重阶段；CPU 模式按索引产生固定宽度字符串。Infrastructure 按最多八条互斥分片启动长期 worker，所有分片共享一个 2 GiB Windows Job 和 20/50/80% CPU 硬上限，不把百万候选展开成字符串列表。公开头归档重用已打开 handler，加密头在固定 handler 上重新打开，每候选均使用独立密码回调。

轻量加密条目必须完整解码与校验，全包受限空流校验成功才返回密码。进度以各 lane 实际完成的候选数累计，提前成功保留真实百分比。取消同步通知整个池，以一个五秒期限终止未退出进程；原文件及相关分卷在整个任务期间持有只读句柄。密码和候选不进入日志、设置、命令行或临时文件。

## V0.7 图片混淆

图片排列使用独立 `IImageObfuscationEngine`、`ImageObfuscationRequest/Progress/Result` 与 `SerialImageObfuscationQueue`，不进入媒体转换预设。Desktop 维护混淆/解混淆任务和当前页可见队列，复用全局忙碌、取消、导入及窗口退出生命周期。模式和次数是非敏感设置，旧设置缺省为 Gilbert/1。

Infrastructure 先检查静态格式与资源限额，将图片归一化为正常显示方向的 PNG，随后由有界二进制管道获取非预乘的 8/16 位 RGBA。Gilbert 路径移植自固定版本 BSD-2-Clause 原始实现；方块/全像素使用原创稳定版本 SHA256 字节流和确定性排列，完整移动 RGBA，不丢余边。次数仅在同模式内重复；已有应用标记的输入不能再次混淆。

PNG 的有界 tEXt 标记记录公开的算法版本、模式、次数、尺寸、位深与原像素摘要，无密码。解混淆优先使用有效标记并校验原像素摘要；无标记输入仅按人工参数尝试，返回 `Verified=false`。编码后重新解码比对，成功后才以不覆盖方式提交；取消/失败仅删除任务拥有的临时 PNG。没有明文 raw 临时文件，也没有图片服务器依赖。

## V0.8 桌面陪伴

`App` 统一持有主窗口、共享 `MainViewModel`、`PetController`、托盘及用户会话单实例互斥量。关闭启用桌宠的主窗口仅隐藏，明确退出才取消并等待任务。命名管道只接受当前用户的唤回命令。桌宠与提醒窗使用独立的非激活透明窗口，不依附主窗口最小化生命周期。

Core 新增 `FileProcessingAction`、导入回执、任务快照和批次摘要。Desktop 在现有四个串行队列回调中发布开始、限频进度和完成事件，实际请求使用独立操作编号；合并打包按请求计数，恢复候选耗尽与找到密码分开。桌宠选择功能后走原导入与参数页，忙时只暂存路径。外部展示观察者异常不会改变已提交结果。

`PetStateStore` 单写入器保存余额、背包、配饰、休闲工作剩余时间和最近批次结算记录。确认交易先落盘，再更新展示；写失败保留待结算奖励。工作只累计有界单调时钟片段，隐藏、忙碌和离线不累积。账户与共享设置分别保存，避免互相覆盖。sprite 图集、定位参数和制作提示词作为本地资产随包提供，隐藏停止所有表现 clocks 与计时器，关闭桌宠卸载环境检测。

## 本机数据与发布

设置与有限大小的诊断日志保存到 `%LOCALAPPDATA%\CatFileAssistant`，不上传。测试通过依赖注入使用独立设置目录，避免修改真实用户设置。正常界面不展示 FFmpeg 原始输出，诊断详情供需要定位问题的用户查看。

正式发布为自包含 `win-x64` 便携程序，携带 .NET 桌面运行环境及 FFmpeg 共享引擎，不携带开发 SDK。FFmpeg 可替换；许可与来源随发布包提供。旧 PowerShell 原型保留在源码仓库供对照，不作为新版发布入口。

未来微信小程序可沿用格式标识、状态命名、错误规范和视觉资源，使用自己的界面及执行引擎适配器。WPF 与 Windows FFmpeg 进程实现不能直接搬入小程序；小程序的处理方式、系统文件访问能力与部署方式需要另行确定。本版本保持本机处理，不建设转换服务器。

The source/ directory contains the complete source and project needed to build
the worker. It does not reference the desktop application, Core, FFmpeg, or
third-party NuGet packages. No archive algorithm is reimplemented here.

Requirements: Windows x64 and .NET 10 SDK. The original development SDK was
10.0.401. The portable application already includes the runtime and does not
require its users to install an SDK.

From this directory:

```powershell
dotnet publish .\source\CatFileAssistant.ArchiveWorker.csproj -c Release -r win-x64 --self-contained true -p:PublishSingleFile=false -p:PublishTrimmed=false -o .\rebuilt
```

After closing the application, replace the application's worker/ directory with
the rebuilt output. Preserve the source and licenses when redistributing a
modified worker. This component may be modified and replaced; reverse engineering
for debugging modifications to LGPL components is permitted.

The compatible complete official x64 7z.dll is loaded by absolute path using its
exported factory, without system COM registration. A replacement compatible DLL
may be selected through the application settings. 7za.dll/7zxa.dll do not provide
the complete format set and cannot be substituted as an equivalent engine.

Password-bearing requests arrive on anonymous stdin pipes; stdout uses JSON lines
for progress and a final result. Passwords are never command-line arguments or
persisted files. The parent supervises the worker with a Windows Job Object.

V0.6 also exposes read-only numeric password recovery through the same worker.
The recovery lane accepts one request and tests its disjoint candidates without
restarting the process for each password. Native encrypted-content verification
uses bounded null output streams and does not create extracted files. The
parent owns one shared CPU/memory-bounded job and a five-second pool cancellation
deadline. Recovery.cs is included in the corresponding source distribution.

7-Zip's unRAR-derived decoding code cannot be used to recreate a RAR compression
algorithm. This application exposes RAR decoding/verification only.

# V0.5 打包压缩与解压缩

## 打包压缩

在左侧选择「打包压缩」，添加普通文件或文件夹，也可以拖入。不同类型的文件可以一起打包，文件内容不会经过媒体转换。

默认 ZIP、标准档位、合并打包、不加密、不分卷。合并模式把所有待处理输入组成一个包，可填写名称；分别模式为每个文件或文件夹生成独立包。目录保留根目录名、内部层级和空目录。父目录已经包含的子输入不重复添加；不同来源的同名根自动编号。

| 创建格式 | 档位 | 密码 | 分卷 |
|---|---|---|---|
| ZIP | 存储、快速、标准、高压缩 | AES-256；文件名可见 | 无 |
| 7Z | 存储、快速、标准、高压缩 | AES-256；同时加密文件名 | 可选 |
| TAR | 仅打包 | 无 | 无 |
| TAR.GZ | 快速、标准、高压缩 | 无 | 无 |

ZIP 使用 Deflate，7Z 使用 LZMA2。档位控制速度和压缩率的取舍，不控制清晰度。已经压缩的视频、图片等可能缩小很少，或因包头略微变大。程序显示实际输入大小、输出大小和节省比例，不承诺固定比例或最终总大小。

**创建加密 ZIP 时，密码限 1–99 个可打印 ASCII 字符**，可以包含英文字母、数字、空格和符号。这是所用官方引擎的创建限制；中文或 emoji 密码请选择 7Z。7Z 密码最多 1024 个字符。所有密码禁止换行和空字符。密码不保存到设置、日志、临时文件或命令行，批次结束、清空、切换页面及退出时清除当前会话的密码。

加密 ZIP 应使用本软件、7-Zip 等兼容工具解压，不保证 Windows 自带解压支持。ZIP 加密不隐藏文件名；7Z 加密同时保护文件名。

7Z 分卷提供 100 MiB、500 MiB、1 GiB 和自定义选项，最小 1 MiB。1 MiB = 1,048,576 字节。设置限制每个卷的大小，不限制压缩后的总大小。所有卷保存在一个独立文件夹中，名称为 `包名.7z.001`、`.002` 等；请一起保留和发送所有卷。

## 解压缩

支持 ZIP、7Z、RAR、TAR、TAR.GZ、GZ、BZ2、XZ、TAR.BZ2 和 TAR.XZ。RAR 仅解压。TAR 压缩组合会解开外层后继续读取 TAR；GZ/BZ2/XZ 单一压缩流生成一个普通文件。普通包中的其他压缩包不会自动递归解开。

每个压缩包输出到独立文件夹，同名自动编号，不混入已有目录。可以填写共用密码，也可为单个任务设置密码。所有分卷必须在同一文件夹，多次添加同一组卷会归并为一个任务；缺卷、错误密码和损坏包会显示原因，不提交不完整结果。

默认解压保护为最多 100,000 条目、64 层目录、累计写入 100 GiB，可在设置中调整。TAR 包装层的中间文件也计入累计写入量。独立归档工作进程的内存上限为 2 GiB；超过限额或磁盘空间不足时失败并保留原包。

程序拒绝路径穿越、绝对路径、系统设备名、附加数据流、大小写冲突、链接、设备及其他特殊条目，只写普通文件和目录，不恢复特殊权限。安全检查先于实际内容写入。

## 文件保护与停止

创建先形成输入清单并保存任务专属快照，再写入临时压缩包。源目录内部也可以作为保存位置，本任务产生的临时文件不会被纳入输入。源文件无法完整读取、发生可检测变化或验证失败时，整个包失败，不静默遗漏文件。

单包先验证完整性，再无覆盖提交；分卷先验证完整包，再切片并验证重组结果，最后整体提交分卷文件夹。解压先写入任务临时目录，所有条目和完整性检查成功后整体提交。过程中百分比最多 99%，提交成功才显示完成。

停止会取消当前任务，保留尚未开始的任务和已完成结果。取消超过五秒会终止该任务工作进程；失败或停止只清理该任务拥有的临时目录。完成后可以再次添加同一输入，创建下一批任务。

快照、临时包、校验与分卷可能同时占用磁盘空间，请为大批量操作选择有足够可用空间的位置。所有处理都在本机进行。

## 组件与许可

使用未经修改的官方 7-Zip 26.04 完整 x64 引擎，保留 LGPL、BSD 和 unRAR 限制。对应官方完整源码、归档工作进程及互操作层源码和构建说明随包提供；不捆绑 WinRAR，也不提供 RAR 创建。详见根目录第三方说明和 `licenses/7zip`、`licenses/archive-worker`。

开发可运行 `scripts/bootstrap-archive-engine.ps1` 校验固定引擎和源码。初次解出引擎需要开发机已有归档工具，可传 `-ExtractorPath`；这不影响用户便携包独立运行。

验收运行：

```powershell
.\tools\dotnet\sdk\dotnet.exe run --project .\tests\CatFileAssistant.Acceptance -c Release -- --root . --archive-only
```

`--archive-only` 适合定位归档问题，不替代全量正式发布验收。

# V0.3 文件压缩

在左侧选择「文件压缩」，点击拖放区或添加文件，也可以拖入视频、音频和图片。一个队列可以包含不同类型的文件，程序自动识别。

## 选择大小

「快捷压缩」提供四个输出大小上限：大为原体积的 80%，中为 50%，小为 30%，超小为 15%；默认选中。每个文件独立计算目标，实际结果可能小于上限。

「指定大小」填写每个文件的最大 MB，默认 10，支持小数。1 MB = 1,000,000 字节。上限不是整个批次的总大小。无效输入会显示错误并禁止开始。

目标越小，清晰度或音质可能越低。程序先调整编码参数，再按需要缩小图片和视频尺寸或降低音频参数。最多尝试八轮，仍无法满足时显示失败和调整建议，不提交超限结果，也不通过截断时长或静默删除声音来缩小文件。

## 输出格式

优先保留源扩展名和容器，内部编码可以改变。直接支持：

- 视频：MP4、MOV、M4V、MKV、WebM、AVI。
- 音频：MP3、M4A、AAC、WAV、FLAC。
- 图片：JPG/JPEG、PNG、WebP、BMP、GIF，包括动态 WebP。

其他能够读取的格式可以进入队列，但需要在该文件旁选择兼容的输出格式后才能开始。候选会考虑动画和透明背景。PNG、BMP、WAV、FLAC 保留格式时可能通过缩小尺寸或降采样达到目标，因此不能理解为相对原文件仍完全无损。

GIF 与动态 WebP 采用完整动画处理，保留一轮时长、循环设置和兼容的透明效果。压缩页不会将动态图静默变成第一帧。

自定义上限下，源文件已经符合大小要求且保留原格式时，会直接另存一份，并显示「已符合上限」和 0% 节省。

## 批量操作与文件保护

修改压缩设置时，有选中行就应用到可编辑的选中任务，否则应用到全部可编辑压缩任务；同时更新后续添加文件的默认方案。完成的记录不变，逐行选择的输出格式不会被档位修改覆盖。

转换和压缩任务分别显示、启动、清空和重试，同一原文件可以同时有转换与压缩任务。处理期间禁止修改设置或切换功能。

所有文件都在本机处理。原文件保持不变，结果先写入任务专属临时文件，体积和媒体检查通过后再另存；同名结果自动避让。取消或失败只清理该任务的临时产物，成功结果继续保留。

队列在完成后显示原大小、输出大小和节省比例。失败时点击「查看原因」，可查看建议及折叠的技术诊断。

# V1.0 桌面猫咪与首页陪伴

桌面猫咪沿用银渐层角色，以本地文件处理和轻松陪伴为主。首次启动默认开启，软件侧栏底部的“猫咪桌宠”可打开独立页面，包含互动、待处理文件、喵喵商店、背包和设置。关闭主窗口会收起到托盘；彻底退出请用猫咪或托盘的退出菜单。关闭桌宠后，主窗口沿用正常退出流程。

## 首页的猫咪休息角

首页下方设有猫咪休息角，使用原桌宠图集和动画播放器。首页和桌面猫咪由同一个控制器管理，共享文件处理、休闲工作、互动、睡眠、朝向及装扮，也使用同一份喵喵币、背包和工作进度。关闭桌面猫咪后，首页仍可陪伴；不会新建另一份宠物账户或重复发放奖励。摸摸猫咪或点击“摸摸头”“一起玩耍”会触发共同的回应，“喂食”和“商店与背包”打开原有背包与商店。

每次启动后，首次展示首页猫咪时，从本机当前时段的台词池随机选择问候，并播放现有招呼动作。例如早间“早上好喵！”、晚间“晚上好喵！今天辛苦啦。”，也可能选到“你来啦，今天要做什么呢？”等通用台词。返回首页、恢复窗口或切换主题不会重播启动问候；已有文件处理、正在进行的休闲工作、互动、结果提示或存档错误时，问候不会覆盖这些状态。问候只使用文字和已有动作，不播放语音，也不调用语音、网络或云端服务。

软件内的猫咪只在首页展示。首页为当前页且主窗口未隐藏、未最小化时，视图加入原控制器；离开首页、隐藏、最小化或关闭主窗口时，移除预览注册并停止该视图的帧、呼吸和过渡时钟。恢复首页后继续共同状态，不重新创建账户。首页与桌面同时显示时，仍只使用一个陪伴心跳和一套工作计时。

## 把文件交给猫咪

拖入文件或右键选择“处理文件”，再选择文件或文件夹。猫咪展示软件的全部 11 种功能及可接收数量，选定后进入原参数页，选择格式、画质、保存位置并点击开始。文件夹只进入打包功能，分卷沿用压缩包导入规则。正在处理时只暂存文件路径，结束后由用户选择下一步，不自动执行。混合输入中不适合所选功能或已移动的文件会保留，原因在“待处理文件”中显示；可以清空后重新选择。正式退出会清空待选列表。

猫咪的工作状态来自四类真实任务队列，显示当前任务、阶段、批次序号与实际进度。未知进度不伪造百分比，结果检查并提交后才显示完成。部分失败、取消及密码未找到有各自的提示。提醒不播放声音、不抢焦点；有输出时可以打开结果目录，失败时可以回到任务页查看原因。恢复密码和候选数字不会进入桌宠快照或存档。

## 持续轻柔动画

待机呼吸周期为 3.2 秒，高度变化最多 1.5%；睡眠为 4.8 秒、最多 1.2%。动作以脚底或卧姿底部为支点，眨眼间隔内仍保持轻微动态。清醒待机每 15–30 秒穿插舔毛或伸懒腰，睡眠期间不插入清醒动作；走路、拖动及明显互动由对应动作接管。睡眠六帧使用各自完整裁切范围和共同透明画布，保留尾巴与安全边距。猫咪、过渡画面和配饰一起微动，点击区域同步变换。

桌宠具有独立的“持续轻柔／跟随 Windows／减少动效”设置，同时应用于首页猫咪和桌面猫咪。“持续轻柔”为默认值，即使 Windows 关闭窗口动画，猫咪仍以限制帧率的方式保持呼吸与动作；“跟随 Windows”按系统动画设置播放；“减少动效”保留静态表情与文字。这不改变软件其他页面的动画设置。桌面猫咪隐藏、锁屏或退出时停止该窗口的动画，首页猫咪按上文的页面和窗口生命周期停止。升级旧版本时，曾明确选择减少动效的用户继续保持减少动效，其余旧配置迁移为持续轻柔；已经保存的独立桌宠模式保持原值。

## 陪伴与喵喵币

短按猫咪会随机回应，点击头部会摸头；按住 300 毫秒后可拖动。默认偶尔短距离走动，睡眠、工作、菜单、拖放及互动时停止走动。走动可以独立关闭。猫咪具有待机眨眼、舔毛、伸懒腰、睡眠、左右走路、喂食、玩耍、休闲工作、文件处理和结果回应动作。罐头与小鱼干、逗猫棒与毛线球使用不同道具动作。

初始赠送 30 喵喵币。实际成功的每个处理请求奖励 5 币，合并打包奖励一次；压缩多轮校准、重复通知不重复奖励。失败、取消和密码未找到不奖励，部分成功按成功请求计算。手动开始工作后，每分钟获得 4 喵喵币，累计完整秒数，整段收入向下保留两位小数：10 秒为 0.66 币，15 秒为 1 币，1 分钟为 4 币。不会在五分钟自动结束；最小化、隐藏桌宠、游戏和处理文件、互动期间继续累计，锁屏和系统休眠暂停，不运行额外计算任务。

工作页显示本次累计时长与收入，账户余额只显示已成功保存的金额。每 30 秒原子保存并入账本次尚未确认的收入，购买物品时先在同一笔交易内确认最新收入；停止或彻底退出时结算剩余收入并保留本次总结。再次开始才清零本次计时。停止后播放庆祝动作与随机文字台词，不播放语音。保存失败时不确认收入，暂停累计，允许重试同一份结算。突然退出后仅恢复最后一次成功保存的工作进度，完成该段结算并停止工作；不补算离线时间，正常情况下最多损失最后 30 秒未保存的进度。旧版未完成工作按已有进度一次结算，已有余额、背包、装扮及文件奖励记录保留。

## 安静与性能

桌宠是独立的小透明窗口，不占任务栏，不夺取前台焦点；透明留白可穿透操作。默认大小 160 DIP，可选 120、160、200。位置自动限制在显示器工作区，并兼容负坐标、多屏及 DPI 变化。

默认自动检测独占全屏、无边框全屏及演示；窗口化游戏可在设置中指定准确的程序名，例如 `game.exe`。指定程序在前台时隐藏，返回后只汇总一次完成结果。锁屏也暂停。识别结合 Windows 通知状态、前台事件及每两秒一次检查，不扫描所有进程或注入游戏。这里检测的是适合安静的窗口状态，不承诺自动识别所有游戏品牌。

图集播放时钟、连续微动和短过渡为 30 FPS，走动位置更新上限 60 FPS，任务反馈最多每秒四次。沿用每个动作的原有六个绘制姿势：工作每姿势 180 ms，走路 90 ms，喂食 240 ms，玩耍 160 ms，睡眠 500 ms。在相邻姿势间使用最长 100 ms 的淡化、同步插值配饰位置；眨眼保持清晰切换。这些过渡不等同于 30 个独立绘制姿势。休闲工作期间可以暂时播放喂食、玩耍与摸头回应，工作计时继续；真实文件处理保持工作提示的优先级。解码按显示用途限制到每格最多 256 像素，共享图集缓存上限 24 MiB；桌面猫咪隐藏时停止该窗口的动作、呼吸、拖动与走动计时器，禁用桌宠时卸载游戏检测。首页预览复用同一图集缓存，离开首页即停止自身动画。微动不增加图像解码或文件读取，也不改变文件处理参数。

# V0.4 视频转 GIF

在左侧选择「视频转 GIF」，点击中央区域或「添加文件」，也可以拖入视频。选择画质与保存位置后，点击「开始生成 GIF」。支持整段视频批量处理，输出无声音并无限循环。

## 五档画质

| 档位 | 最长边上限 | 帧率上限 | 色数上限 |
|---|---:|---:|---:|
| 原画 | 原尺寸 | 保留全部帧 | 256 |
| 高 | 1280 像素 | 30 fps | 256 |
| 中 | 800 像素 | 20 fps | 128 |
| 低 | 480 像素 | 12 fps | 64 |
| 极低 | 240 像素 | 6 fps | 32 |

首次默认中档，以后记住上次选择。保持画面比例和正常播放方向；小视频不放大，低帧率视频不升帧。降低档位通常会减少体积，也可能减少细节、流畅度或颜色层次。最终大小取决于内容与时长，不是固定比例，GIF 也可能比原视频更大。

**原画保留原尺寸，不主动抽帧；颜色和帧时序受 GIF 格式限制。** GIF 每张图像的色表最多 256 色，延时以 10 毫秒为单位，因此无法完全无损表示任意视频。60 fps 等视频会量化帧延时，播放器还可能限制短延时。若真实帧时序无法在保留全部帧的同时正确表示，原画档明确失败并建议选择高档，不自动降低档位或拉长播放。[GIF89a 规范](https://www.w3.org/Graphics/GIF/spec-gif89a.txt)

## 批量设置与结果

有选中行时，修改档位应用到可编辑的选中 GIF 任务；没有选中行时应用到全部可编辑 GIF 任务。两种操作都会更新后续添加文件的默认档位。完成记录保持原设置，失败或取消的任务可以改档后重试。

GIF、普通转换和压缩分别显示、开始、清空和重试。同一原视频可以分别添加到三个功能。处理期间无法导入、切换功能或修改档位。每项完成后显示实际使用档位与「原文件大小 → GIF 大小」。

首版不提供片段截取或指定大小。GIF 不包含音轨和独立字幕，已经画在视频画面中的文字会保留。

## 本地处理与文件保护

文件只在本机处理。结果先写入任务专属临时文件，检查格式、尺寸、帧数、循环、时长和完整解码后再保存；一轮时长误差不超过 20 毫秒。同名结果自动编号，原文件保持不变。

停止或失败只清理当前任务的临时产物，已完成结果保留。单项失败后继续处理其他任务；失败时点击「查看原因」可查看建议与高级诊断。

# V0.7 图片混淆与解混淆

在“更多工具”选择“图片混淆”或“图片解混淆”。支持 JPG/JPEG、PNG、BMP、静态 WebP，批量串行处理，统一另存无损 PNG。动态图、APNG、多页图片不支持，不会静默只处理第一帧。超过 1600 万像素或单边超过 8192 的图片会明确拒绝，不自动缩小。

## 三种模式

| 模式 | 行为 | 实现来源 |
|---|---|---|
| Gilbert | 沿二维 Gilbert 曲线，以固定黄金比例偏移排列完整像素 | C# 移植自 Jakub Červený 的 BSD-2-Clause 公开遍历实现；偏移和处理流程由本项目实现 |
| 方块 | 将 32×32 方块重排；同尺寸余边单独分组，保留所有边缘像素 | 本项目原创确定性置换 |
| 全像素 | 重排画面中的完整 RGBA 像素 | 本项目原创确定性置换 |

无需输入密码；算法和默认参数是公开的，任何掌握相同算法的人都可以恢复。它是视觉混淆，不能作为安全加密、机密存储或版权保护方案。方块模式对小于一个方块的图片可能没有明显效果，可改用全像素。

首次默认 Gilbert、一次处理，记住模式和次数；次数可选择 1–10。每个请求中的多次操作使用同一模式。已带本软件混淆标记的图片不能再次混淆；请先解混淆，或直接在首次操作选择次数，避免丢失上一层恢复信息。

## 恢复与文件保护

本软件生成的 PNG 内嵌有界、非秘密的版本、模式、次数、尺寸及原始归一化像素摘要。解混淆会自动采用这些参数，并校验像素摘要。缩放、裁剪、编辑像素或有损压缩可能使校验失败；建议发送原始 PNG 文件。不要将 PNG 再转换为 JPG。

无标记图片按界面选择的模式和次数尝试，完成状态明确标注“未校验原图”，需要自行核对。图片本身无法可靠推断外部工具、密钥、次数和原始内容；错误参数也可能生成有效但错误的图片。不能保证恢复使用其他密钥、其他排列规则或未经验证的第三方输出。

可逆保证针对归一化显示方向后的解码像素，包括透明通道和 8/16 位 PNG 精度；不承诺恢复原 JPG 文件的压缩字节、原文件格式或全部原始元数据。源文件不修改，输出自动避开同名文件和目录，失败/停止只清理本任务的临时文件。结果提交并核验后才显示完成。

输入文件最多 256 MiB；带符号链接或重解析目录的路径需先复制到普通目录。程序从锁定的源句柄创建任务专属临时快照，确保检查和解码使用相同内容，结束后删除快照。像素数与边长限制控制主要内存需求，不代表所有进程总内存的硬配额。

所有处理在本机执行，不连接第三方图片服务。仅处理自己拥有或已获授权的图片；本功能不提供移除水印、伪造署名或绕过内容访问限制的操作。

## 状态与保护

业务 `AssistantState` 保持原五种状态。悬停、眨眼和睡眠仅属于显示层。`CompletionCue` 只在当前非空批次全部成功后递增，拖拽退出或窗口恢复不产生新信号；隐藏控件消费信号但不补播。完成动作后安静待机，成功标记和业务结果仍保留。部分失败使用错误提示，主动停止回到平静等待。2D 替换保持现有状态接口、设置兼容性和 UI 布局。

## 自动行为检查

- 旧配置默认“跟随系统”，“减少动效”保存后重新打开有效，并保留输出目录。
- 成功批次只生成一个新的完成 cue；拖入后返回成功、无待处理任务、部分失败及主动停止均不生成新的成功 cue。完整验收还在真实 FFmpeg 转换中检查这些信号。
- 真实 WPF 图片猫咪接收唯一 cue；重复 cue、隐藏期间收到 cue、最小化恢复、移出再加入控件树都不补播庆祝。内部测试 scope 强制启用应用动效策略，覆盖真实动画及 Reduced 两条路径，退出后恢复；Windows 设置保持原值并记入报告。

## 性能采样

在保持可见的本地桌面及 60 Hz 显示器条件下运行：

```powershell
.\scripts\measure-motion.ps1
```

程序通过内部测试 scope 启用应用动效策略，原系统 `ClientAreaAnimation` 和 override 均单独记录。scope 不改变 Windows 设置，Reduced 用户偏好仍生效。程序先生成 640×360、30 fps、20 秒的真实输入，在可见的主窗口中使用同一 H.265 预设。启用和减少动效各预热一次，然后交替执行各三次转换。导入时间不计入转换耗时；完整转换过程包括输出验证及提交。每次检查输出确实提交成功，并在最后核实输入 SHA-256 未变。

| 指标 | 采样与判定 |
|---|---|
| 空闲调度帧间隔 | 正常动效路径初始布局及 JIT 稳定后采样 5 秒；至少 30 个有效间隔，P95 ≤ 20 ms |
| 转码期间调度帧间隔 | 启用动效的三次实际转换分别采样；各至少 30 个间隔，P95 ≤ 20 ms |
| 减少动效调度帧间隔 | 静态路径三次转换独立记录，不能套用正常动效路径的通过结论 |
| 悬停响应 | 24 次悬停属性改变到下一次 Rendering 回调；最大值 ≤ 100 ms，并报告 P95 |
| 转换开销 | 启用与减少动效各三次耗时中位数的绝对差 / 减少动效中位数 ≤ 3% |

`CompositionTarget.Rendering` 记录的是 UI/渲染调度回调间隔，使用 Stopwatch 计时并排除同一 RenderingTime 的重复回调。它不测 GPU 实际呈现帧耗时，不能直接证明每秒 60 个画面已呈现。悬停测试也不包含物理鼠标、操作系统输入或显示器扫描延迟。报告中的采样频率仅表示回调频率。

如果受控启用未生效、回调样本不足或任一预算超出，报告保留数值且专项运行返回失败。不要通过扩大预算或忽略慢帧将结果改为通过。可在记录原因后，于稳定的目标设备再次执行独立采样；不同设备结果分别保存。

程序保存真实宿主 DPI、渲染 tier、系统动画开关和 Windows 版本；脚本额外记录 CPU、内存、显卡驱动、分辨率及查询到的刷新率。WMI/CIM 不可用时保留查询错误，并只读获取注册表 CPU 名称、GlobalMemoryStatusEx 内存和 EnumDisplayDevices 显示设备。替代查询不提供的刷新率、驱动版本明确标为缺失，不臆造硬件数据或改变系统设置。

# V0.6 压缩包密码恢复

在“压缩包工具”中选择“密码恢复”，添加你有权访问的 ZIP、RAR4/RAR5 或 7z。支持现有首卷识别，所有分卷须位于同一目录。恢复只读取压缩包，不修改原文件，不生成解压文件，也不上传文件或密码。

## 两种恢复方式

“常用密码推测”首先测试所选长度的完整常用数字，再测试少量变体，最后尝试内置数字模式。管理窗口可添加、删除、清空或逐行粘贴；最多 100 条，每条为 1–20 个数字 0–9，保留前导零并合并重复项。

变体规则：较长输入取前面和后面的指定长度；较短输入分别在左侧补零、右侧补零，以及重复原数字至足够长度后截取。不同输入不会相互组合。生成结果只保留当前选择的 4 位或 6 位，跨阶段去重。比如 6 位模式中，`1998` 可产生 `001998`、`199800`、`199819`。候选耗尽会显示未找到，不自动转入全量穷举。

“CPU 破解”测试所选长度的全部数字组合，4 位为 10,000 个，6 位为 1,000,000 个，包含 `0000`、`000000`。不支持其他长度、字母符号、GPU 或断点续跑。可批量添加，每个包依次恢复，同一个包内部并行测试。

## 强度、进度和取消

高、中、低档对应恢复进程池 CPU 占用上限约 80%、50%、20%。每个包最多使用 8 个工作进程，总内存上限为 2 GiB。实际占用可能更低；系统不支持 CPU 配额时用工作/等待节流并显示“近似限制”。首次默认常用推测、4 位、中档，之后记住非敏感设置。

建议在高算力计算机上使用。加密算法、密钥派生参数、固实压缩、文件大小、存储和电脑性能都会影响速度，不承诺固定完成时间。

进度表示完成测试的候选数，显示百分比、已测试/总候选和剩余组合。正在测试的候选仍计入剩余。候选通过一个加密条目完整解码与 CRC/认证检查后，还会完整校验全包，期间显示“正在完整验证”。提前找到密码会保留真实已测比例，不把未测试组合计作完成。

可以随时取消；先请求所有工作进程停止，五秒仍未收尾时统一终止本次进程池。未开始的任务及已恢复结果保留，重试已取消任务从头测试。关闭窗口时可以选择继续任务，或停止并等待清理后退出。

## 结果与隐私

找到并完整验证密码后可显示、复制，或点击“使用此密码解压”。转入现有解压页面后由你选择保存位置并开始解压，不自动释放压缩包内容。

候选耗尽属于正常结果。若曾有候选通过部分校验但全包失败，会提示可能损坏或不同条目使用不同密码，不报告恢复成功。无可验证加密内容的空包、不支持的算法、缺卷、读权限及资源/解压保护限额问题会分别提示。

用户常用数字只在本次软件会话中复用，退出或主动清空即清除；恢复结果在移除任务、清空队列或退出时清除。密码不写入设置、日志、临时文件或命令行，进程间仅通过匿名管道传递。复制密码是用户主动操作，内容进入系统剪贴板。

## 原创数字模式来源

内置规则版本为 `numeric-patterns-v1`，由本项目独立编写，不引用外部密码数据集、泄露库或个人数据。每种长度最多 38 条：10 条同数字重复、20 条从 0–9 各起点循环递增/递减，以及 `12`、`21`、`10`、`01`、`52`、`25`、`69`、`96` 的重复模式。它们是数字模式示例，不代表统计密码排行。

规则实现在 Core 的 `RecoveryCandidates` 中；随包的来源记录含规则版本及生成结果校验值。归档算法仍使用未修改的官方 7-Zip DLL，恢复工作进程对应源码与既有 LGPL/混合许可随包提供。详见第三方组件说明。

每分钟 4 币，以本次累计整秒计算：`floor(seconds × 400 / 60) / 100`。10 秒0.66币、15秒1币、60秒4币。每30秒保存一次，购买、停止、彻底退出同步保存，重复通知不重复发放。保存失败暂停计入新时间，待结算成功后恢复；停止失败不播放成功庆祝。

普通后台运行、文件任务和互动计时；锁屏及休眠暂停。正常退出结算并停止，下次开始清零；异常退出仅恢复最后成功保存的检查点，不计离线时间。

## 动画

保留角色图集与动作内容，30FPS 连续微动和过渡、60FPS 走位，帧切换依据单调时钟。相邻姿态采用短过渡和配饰锚点插值，眨眼维持清晰切换。这里的刷新频率不表示每秒有30张独立绘制的身体姿态。隐藏和减少动效模式停止对应视图时钟。
